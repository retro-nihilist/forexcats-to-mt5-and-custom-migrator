## Описание проекта
Данный репозиторий представляет собой набор инструментов и скриптов для **миграции данных, анализа конфигураций и управления торговыми условиями** собственной торговой платформой («own_platform»). Код ориентирован на автоматизацию работы с котировками, торговыми инструментами (символами), сессиями и финансовыми отчетами.

## Основной функционал

### 1. Управление торговыми условиями (Trading Conditions)
*   **Глобальная настройка символов:** Конфигурирование параметров для различных классов активов (Forex, Stocks, Metals, Crypto и др.), включая размеры лотов, кредитное плечо и режимы расчета маржи.
*   **Гибридная модель маркапов:** Создание и расчет статических и динамических маркапов на основе данных из XLS и CSV файлов.
*   **Управление спредами и свопами:** Расчет желаемой стоимости спредов для клиентских групп и настройка профилей свопов, включая исключения для конкретных инструментов.
*   **Добавление инструментов:** Автоматизированный модуль для поиска и добавления недостающих торговых инструментов на основе данных из внешних систем (например, Finclerk).

### 2. Контроль торговых сессий (Trading Sessions)
*   **Формирование расписания:** Генерация конфигурационных файлов сессий с учетом праздников и перерывов в торговле.
*   **Сезонные изменения (DST):** Автоматическая адаптация расписания под переход на летнее/зимнее время в США, Европе и Японии.
*   **Анализ плотности котировок:** Мониторинг поступления тиков, выявление «дыр» в сессиях и активности вне установленного времени торгов.

### 3. Работа с базами данных и SQL
*   **Интеграция с MySQL и ClickHouse:** Выполнение запросов к CRM-системам, базам цен и истории тиков.
*   **Генерация SQL-дампов:** Извлечение структуры таблиц и очистка данных от «мусора» (NaN, NULL-байты) для создания валидных SQL-запросов.
*   **Синхронизация окружений:** Инструменты для копирования данных между Production и Staging серверами с проверкой прав доступа.

### 4. Корпоративные события и аудит
*   **Контроль сплитов (Splits control):** Поиск акций, по которым планируются сплиты, и идентификация открытых позиций клиентов по этим инструментам.
*   **Финансовая отчетность:** Расчет суммы уплаченного клиентами спреда (с учетом маркапа) и конвертация этих данных в USD для анализа доходности.

## Решаемые задачи
*   **Автоматизация миграции:** Снижение вероятности ошибок при переносе торговых настроек с одной платформы на другую.
*   **Единообразие условий:** Обеспечение идентичности торговых условий (PnL, маржа) для перенесенных сделок, особенно в волатильных активах типа криптовалют.
*   **Визуализация и отчетность:** Генерация красивых HTML и PDF отчетов по расписаниям торгов и аномалиям в спредах для оперативного контроля.
*   **Технический аудит:** Поиск расхождений в котировках между разными поставщиками данных (DB vs FC).

## Структура проекта
Проект организован в виде Jupyter-ноутбуков (.ipynb) и вспомогательных библиотек на Python (.py):
*   `Analysis_MT5_configuration/` — инструменты для парсинга конфигураций MT5 Server.
*   `trading_conditions/` — расчеты торговых параметров, маркапов и условий.
*   `quote_sessions/` — скрипты для работы с временем торгов и тиками.
*   `splits_control/` — мониторинг корпоративных событий.
*   `libraries_py/` — общие библиотеки функций (`yar_sed_general_lib`, `sql_request_2`).

## Директории данных
Код использует стандартизированную структуру каталогов для работы с файлами:
*   `original_data/` — исходные CSV/XLS файлы с настройками.
*   `working_data_files/` — временные файлы, созданные в процессе работы скриптов.
*   `log_data_files/` — логи выполнения и история изменений.
*   `output/` — финальные конфигурации и отчеты.
